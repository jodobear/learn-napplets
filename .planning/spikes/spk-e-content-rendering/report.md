# SPK-E — Shared-source content rendering report

SPK ID: SPK-E-CONTENT-RENDERING

Metadata path: metadata.yaml

## Research question

Can one bounded local structured record generate static HTML, guest content, Markdown, a glossary entry, a transcript, and knowledge JSON while preserving the same source, claim, terminology, maturity, uncertainty, and status fields in every representation?

## Conflicts

No rendering mismatch occurred. There is a vocabulary-model limitation: current canonical research records provide stable `SRC-*` and `CLM-*` identifiers but define terminology, maturity, uncertainty, and status as controlled values rather than separate IDs. SPK-E records this fact explicitly and copies the exact canonical values into every output; it does not manufacture a parallel identifier system.

No conflict with upstream protocol evidence was evaluated or resolved. This experiment is restricted to a bounded project-policy record.

## Inference

**Inference:** a future content model can plausibly use one structured record as the common source for the measured human- and machine-facing representations, provided its contract continues to make all required evidence and status fields explicit and validates target parity. This is not evidence that any production renderer, framework, guest protocol, or export architecture is selected or viable.

## Prototype or measurement

No production prototype, application route, framework scaffold, or guest runtime was created. The local `render.py` utility used `fixture.yaml` as its sole content-fact input, generated the six declared formats in `/tmp`, calculated output digests, parsed the parity values back from each format, and emitted a replay manifest. Five runs were compared byte-for-byte.

The completed evidence is the non-production metadata/fixture/recipe/renderer/environment/measurement/report set under `.planning/spikes/spk-e-content-rendering/`. It is a disposable spike fixture, not a production content pipeline.

## Recommendation

**Project recommendation, not an accepted ADR:** retain SPK-E as a passed, non-production proposed evidence input for ADR-0004 (content source model). The result supports requiring a future content model to derive essential human and machine representations from one structured source with field-level source/status parity. Phase 2 must still obtain the required product/content-contract review before choosing or implementing a production renderer, framework, route, or guest integration.

## Uncertainty

Uncertainty remains limited for this local parity observation and material for any production or protocol conclusion. The experiment proves only that this bounded synthetic/project-policy fixture and local templates can retain selected values deterministically. It does not establish upstream behavior, semantic completeness for all future content, accessibility of a real interface, security of a runtime boundary, LLM quality, or approval of ADR-0004.
