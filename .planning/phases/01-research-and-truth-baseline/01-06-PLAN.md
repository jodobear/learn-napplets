<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mutable upstream state → refresh comparison | Changed and unavailable inputs must not masquerade as unchanged evidence. |
| compatibility evidence → ADR recommendation | An incompatible baseline can distort an architecture decision. |
| refresh output → accepted claim history | Automated change detection has no authority to revise meaning or approval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Tampering | refresh source comparisons | high | mitigate | Compare resolved commit/blob/digest, retain historical pointers, and emit stale/blocked impacts. |
| T-06-02 | Tampering | compatibility matrix | high | mitigate | Require one immutable baseline and public-export evidence for every row. |
| T-06-03 | Repudiation | current-work interpretation | medium | mitigate | Label issues/PRs/discussions directional, include retrieval dates and source references, and map revisit triggers. |
| T-06-04 | Denial of Service | concurrent refresh | medium | mitigate | Use deterministic review-work identity and explicit conflict failure rather than concurrent record mutation. |
| T-06-SC | Tampering | local comparison tooling | high | mitigate | Run on the Plan 01 approved environment and preserve records for human review. |
</threat_model>
