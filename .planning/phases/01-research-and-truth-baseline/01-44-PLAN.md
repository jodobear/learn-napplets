<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| approved top-level scope → derived closure | Resolver-selected transitive members must stay exact, policy-checked, and inside the approved scope. |
| wheelhouse archive → fresh environment | A substituted archive or network/index dependency could change executed tool code. |
| installer output → wrapper forwarding | Installed metadata alone cannot prove archive provenance or RECORD integrity. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-44-01 | Tampering | wheelhouse closure | high | mitigate | Task 1 rehashes every compatible binary archive and compares it to the exact lock and sorted manifest before target creation. |
| T-44-02 | Spoofing | installer provenance | high | mitigate | Task 1 requires `file://` report entries matching manifest archives and binds each installed distribution to one archive. |
| T-44-03 | Tampering | installed target | high | mitigate | Task 1 compares wheel metadata/RECORD with installed files/RECORD and attests the actual fresh interpreter. |
| T-44-04 | Elevation of Privilege | wrapper command forwarding | high | mitigate | The wrapper bootstraps first and refuses forwarding when any verification input is missing or changed. |
| T-44-SC | Tampering | previously approved package installation | high | mitigate | The Plan 01-01 human approval covers only top-level packages; this plan uses an offline, hash-required fresh build and blocks policy/scope deviations. |
</threat_model>
