<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source/implementation evidence → conflict records | Contradictory and incomplete input must stay attributable. |
| compatibility assertion → architecture recommendation | Mixed revisions could produce an unsafe or false implementation recommendation. |
| refresh detection → existing accepted evidence | Changed sources must generate review work, not alter claim meaning. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Tampering | drift register | high | mitigate | Require parallel sources, identity, impact, history, and explicit disposition rather than overwriting a record. |
| T-03-02 | Spoofing | compatibility baseline | high | mitigate | Validate every foreign reference against canonical stable IDs and immutable revisions. |
| T-03-03 | Repudiation | open question routing | medium | mitigate | Require owner, resolution criteria, source links, and affected decision/phase lists. |
| T-03-04 | Denial of Service | malformed records | medium | mitigate | Fail closed with compact diagnostics before reports or recommendations consume records. |
| T-03-SC | Tampering | YAML/schema toolchain | high | mitigate | Use the reviewed isolated tools and validator established by Plan 01 and Plan 02. |
</threat_model>
