<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| acquired upstream bytes → canonical YAML | Untrusted/mutable network content becomes an auditable local record. |
| YAML/schema input → validator | Human-edited documents must not execute code or create dangling evidence links. |
| validation result → review status | Automated metadata checks must not impersonate human protocol approval. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-02-01 | Tampering | source registry | high | mitigate | Require resolved commit/blob identity, SHA-256, immutable locator, and preserved freshness metadata. |
| T-02-02 | Elevation of Privilege | YAML parser | high | mitigate | Use only human-approved `safe_load`, Draft 2020-12 structural validation, and strict semantic links. |
| T-02-03 | Repudiation | claim verification state | high | mitigate | Keep owner, required review, uncertainty, and approval evidence separate from automated validation. |
| T-02-04 | Denial of Service | malformed record graph | medium | mitigate | Emit bounded compact diagnostics and reject duplicate/dangling IDs before report generation. |
| T-02-SC | Tampering | approved Python packages | high | mitigate | Consume only Plan 01’s reviewed and pinned isolated toolchain. |
</threat_model>
