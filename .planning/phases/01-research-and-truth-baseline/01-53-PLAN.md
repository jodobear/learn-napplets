## Trust Boundaries
| Boundary | Description |
|---|---|
| repaired evidence baseline → independent verifier | Earlier successful runs could conceal a remaining repair failure. |
| candidate executor/runtime identity → independent verifier | A candidate executor or runtime executor could reuse an identity to self-certify the repaired result. |
| clean-worktree command results → independent report | A stale, substituted, incomplete, duplicate, or wrong-commit result batch could be represented as fresh verification. |
| independent verdict → live State/Roadmap | A factual status update could imply an unauthorized downstream decision. |
| staged terminal files → canonical publisher | Partial or tampered staging could update only some live status artifacts. |
