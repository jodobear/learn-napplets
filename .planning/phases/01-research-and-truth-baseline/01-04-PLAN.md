<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disposable spike → evidence record | Experimental behavior must be attributable and cannot become product code by location. |
| environment/measurement input → recommendation | Missing samples or metadata can make browser behavior appear stronger than it is. |
| automated validation → approval state | A green validation must not imply human acceptance or waive mandatory gates. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | spike metadata and measurements | high | mitigate | Require exact command, environment, replay input, all samples, digest, and evidence IDs. |
| T-04-02 | Elevation of Privilege | disposable browser/harness code | high | mitigate | Require isolated non-production paths, fake inputs, no secrets, and explicit browser sandbox metadata. |
| T-04-03 | Repudiation | approval/governance record | high | mitigate | Separate responsible owner, required approver, dated review state, and automated validation result. |
| T-04-04 | Denial of Service | malformed research files | medium | mitigate | Fail closed before experiment results feed reports or recommendations. |
| T-04-SC | Tampering | approved parser/browser dependencies | high | mitigate | All schema and browser operations use the Plan 01 approved toolchain only. |
</threat_model>
